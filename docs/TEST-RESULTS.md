本文记录 2026-10-13 的历史实验及独立审阅。受测版本、环境、输入与判定依据见下文；各阶段分别列出通过、失败和未覆盖项，原始失败记录及修正过程保留。

## 测了什么

测试任务是用个人技能工坊制作并修改一项借用记录整理技能，再用生成的业务技能处理合成记录。覆盖问答、主动补充、多轮规则更新、去重、来源冲突、日期分类、排序、自由文本中的金额隐藏，以及保留普通备注等要求。

两套环境分别完成四轮制作，以及五批同会话下游执行和一次新上下文 `normal` 重复。code-generator 另执行一次与制作无关的相邻请求。数据为合成数据；没有真实群消息发送或真实业务部署。

| 环境 | 可观察的执行方式 | 身份与能力边界 |
|---|---|---|
| 豆包 | 真实 UI 中的纯聊天；可见设置为“自动 高” | 未独立验证后端型号。助手给出可复制文本，未直接创建本地业务文件；操作者保存文本属于取证归档。 |
| code-generator | 有文件工具的执行环境；制作者、执行者及重复执行者使用新上下文调度 | 角色声明为 `code-generator`、`gpt-5.6-terra / high`，后端型号未独立认证。共享文件系统中的读取范围是指令约束，并非硬隔离。 |

两套环境的工具与交付通道不同，不能视为完全相同条件下的模型横向比较。

## 制作阶段结果

| 项目 | 已观察结果 | 结论范围 |
|---|---|---|
| 一问一答 | 两套四轮制作中，相关断言通过 | 前两轮分别询问输入形式和截止日，没有重复索取已知内容；不推及未来任意输入。 |
| 主动补充 | 两套制作均吸收已提供的业务规则 | 规则进入当前入口或状态。豆包问答历史的来源标注仍有追溯瑕疵，见已知问题。 |
| 多轮生成与修改 | 实际交付初版和修改版，旧版保留，关键当前规则同步 | 文件或文本生成成立，不等于整个制作阶段通过。 |
| 豆包四轮制作 | **失败** | 第四轮“内部核对”说明及新排序样例显示了要求隐藏的金额，同时自评金额隐藏通过：`D7-BF01`、`D7-BF02`。 |
| code-generator 四轮制作 | **失败** | 第四轮用未来到期样例记录“当天到期已验证”，实际未触发当天分支：`C7-BF01`。当前样例实际分类正确，失败在验证结论范围。 |
| code-generator 相邻请求 | **本单例通过** | 直接返回一条 16 字感谢语，没有进入技能制作问答；不代表自动选择率。 |

两套制作中的作者排序样例都实际触发了数量主键和日期次键，且已观察排序正确。作者走读仍属于作者自检，不能计为独立模型验证；排序正确也不能抵消金额泄漏或错误验证记录。

## 下游最终交付

| 批次 | 主要覆盖点 | 豆包 | code-generator |
|---|---|---|---|
| `normal` | 完整重复去重、已清记录排除、日期分类、普通备注 | 通过 | 最终交付通过 |
| `conflict` | 同一实体来源冲突、非法数量、保留已知字段、数据中的指令 | 通过 | 最终交付通过；有业务内容补充 |
| `next-week` | 使用当批新截止日，不混入旧批记录 | 通过 | 最终交付通过 |
| `ordering` | 数量主键、日期次键、金额备注处理 | **失败**：排序正确，备注金额未隐藏（`D7-RF01`） | 最终交付通过 |
| `privacy` | 隐藏受限片段，同时保留普通物品、身份字段、件数、日期及备注 | 通过 | 最终交付通过 |
| 新上下文 `normal` 重复 | 相同任务的业务事实一致性 | 通过 | 最终交付通过 |
| **本次计数** | **每套环境 6 批** | **5 通过 / 1 失败** | **6 / 6 最终交付通过** |

以上是按冻结判据对实际最终输出进行独立语义审阅的结果。两套环境合计 12 批中有 11 批最终通过、1 批失败；这是有限样本计数，**不是可靠率，也不是 12 个独立模型样本**。五批主执行在各自同一会话中顺序完成，自检运行次数不增加模型样本数。

### 同输入重复的具体范围

- 豆包：首次与新对话 `normal` 的完整提示字节相同；业务事实一致，均通过，排版与措辞不同。
- code-generator：首次与新上下文 `normal` 使用同一生成技能、同一输入文件和逐字相同的用户任务正文；完整控制消息因角色说明及输出目录不同而不同。业务事实一致，均通过。
- 重复仅覆盖 `normal` 这个例子，没有证明其他批次可重复稳定，也不能抵消 `ordering` 的失败。

### 原始产物、修正和最终交付

最终通过不表示首次草稿完整，也不表示执行中没有失败。原始产物、修正前版本和最终版本均由维护者独立保留：

| code-generator 批次 | 原始观察及后续变化 | 计分处理 |
|---|---|---|
| `normal` | 首次自检的数字正则过宽，误命中日期；修正自检脚本后通过。三份业务文件修正前后 SHA-256 均未变。 | 业务最终交付通过；保留自检失败，不说发生过业务金额泄漏。 |
| `conflict` | 第一次自检已显示通过，后续走读发现共同借出数量未直接列出；补入回复和清单，并加强断言。两份业务文件发生变化。 | 最终交付通过；不能称首次自检覆盖完整或从未修改业务产物。 |
| 新上下文 `normal` 重复 | 首次自检发生 Windows PowerShell 编码／解析失败；修改脚本后通过。三份业务文件修正前后 SHA-256 均未变。 | 业务最终交付通过；脚本修正不能算新增业务模型运行。 |
| `next-week`、`ordering`、`privacy` | 各保存一次成功自检，没有记录业务修正。 | 最终结果仍由独立全文核对判定，不仅采用执行者的自评。 |

制作阶段的失败不因下游最终通过而改判。自检脚本检查的范围有限，也不能替代对备注、说明文字和完整交付物的语义审阅。

| 类别 | 通过项数 | 实际证明的范围 |
|---|---:|---|
| 工具单元检查 | 33 / 33 | 合成输入下的相应工具行为 |

| 产物契约检查 | 14 / 14 | 指定产物结构与契约 |

另有结构审计 `0 fail / 0 warn`、3 份 JSON 解析以及冻结包 21 个文件的指纹核验。历史单元中的一项旧执行者实际回答复用测试，没有计入本次 73 项。结构审计未进行行为验证。

最初代码回归的完整控制台记录不足，随后另行重跑补采，9 条命令均退出 0；补采记录明确属于后续运行，不能倒称最初已完整留证。RC7 工具审计的原日志事后恢复表明，第三轮实际有 7 次审计：5 次报告写入失败、1 次参数失败、1 次通过。目录／工具失败和业务判定分别保留，不用成功摘要掩盖失败过程。

## 未证实的范围

没有证实任意智能体／任意模型兼容、自动安装与发现、其他宿主及宿主间迁移、冷恢复、长期稳定性、未覆盖的货币写法和自由文本、真实消息发送或真实业务部署。Gemini 的历史补测不计入本轮 RC7 验证。

原始证据仍有明确边界：RC6 首次完整调度明文未恢复；历史进程未经解码的原始字节与独立输出流未恢复；没有审计当时输入的工具级指纹，也没有第四轮映射清理的独立成功证明。事后补录补充可核对证据，不等于最初记录完整，也不改变已确认失败。
